## 12. RE 配送 — 経緯と解消(2026-07-18 解決済み)

- `config/scalar-re-config.yml`(v2 用、.129 MySQL 直結)で ScalarRE は**起動成功**
  (注意: RE の統合設定ローダーは multi-storage モードでのみ contact points を組み立てるため
  storage 2エントリ宣言が必要 — 前身 config と同じ)
- outbox のポーリング・イベント取り出しまでは動作したが、宛先への Put で
  **DB-CORE-10021(クラスタリングキー不一致)**:
  - `ns_mysql.re_inbox`: 既存テーブル(2026-04 の別テスト作成)は `partition` が **INT**、
    現行 RE(6/25 ビルド)は **BIGINT** を書こうとする
  - `scalarre.re_completed`: 既存 PK は (event_type, event_id) のみ、現行 RE は
    (event_type, partition, event_id, step_id, target) を期待
- つまり **.129 上の RE インフラテーブル(scalarre.\*、ns_mysql.re_inbox)が旧 RE
  バージョンのスキーマのまま**だった(4月の別テストの残骸)
- **解消(ユーザー承認 2026-07-18)**: `java -jar demo-scalar-re...jar --recreate-schema
  --scalar-re.config.file=scalar-re-config.yml` で scalarre.\* / viewmgr.re_\* / ns_mysql.re_\* を
  drop→再作成(旧テストイベントは消去。viewmgr.re_outbox も RE 所有スキーマに置き換わったため
  アプリ再起動でメタデータキャッシュを更新)
- 再検証: erp_qty 999→555 の編集 → outbox イベント生成 → **RE がポーリングして
  ns_mysql.re_inbox へ配送成功**(event_id 019f73d9-…、requested_changes + before イメージ)。
  outbox は消化されて 0 件。データ編集画面の俯瞰にも配送済みイベントが表示される
  (宛先キュー表示は選択中 View の RE namespace を動的に使うよう修正)
