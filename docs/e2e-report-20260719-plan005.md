## 実装中の発見と対処(重要)

### 発見1: 同一 Tx 内の「書込後 scan」禁止(DB-CORE-10106)

alias ごとに「scan → update」を繰り返す素朴な伝播実装は、2 つ目の alias の scan が
1 つ目の alias が書いた view 行に重なり `DB-CORE-10106` で拒否される
(`Snapshot.verifyNoOverlap` — scan 結果と write set の交差を禁止)。
**対処**: `UpdateEngine.apply()` を「全 alias の逆引き scan を先に収集 → まとめて update」の
2 段構えに変更(`collectPropagation` / `Propagation` レコード)。

### 発見2: DDL 直後の DML が Cluster ノードの metadata cache で失敗(DB-CORE-10020)

view 再作成(drop→create)直後のマテリアライズ Put が、Cluster ノードに残る旧スキーマの
キャッシュにより「partition key not properly specified」で失敗する。**約 60 秒のキャッシュ失効後は
成功**(リトライループで確認)。デモ運用では view 再作成 → 初回投入失敗時に refresh を
リトライすれば足りるが、恒久対応するなら投入のリトライ内蔵を検討(未実装・backlog)。

### 発見3: tx_state に index を持つテーブルは Cluster 経由で scan 不可(DB-CORE-10281)

RE 配管テーブル(ScalarRE の --create-schema が作成する re_outbox / re_inbox)は
**tx_state に SecondaryIndex を持つ**。Cluster はメタデータ返却時に
`ConsensusCommitUtils.removeTransactionMetaColumns` で tx 列を除去するが、
**secondaryIndexNames に tx_state が残るため TableMetadata.Builder が例外**
(DB-CORE-10281)→ 対象テーブルの scan / metadata 取得が全滅する。
書込み(insert)は影響なし(enqueue は成功)。

**対処(アプリ側)**: 監視パネル(/api/overview)に限り **JDBC 直読(read-only、
tx_state=3 フィルタ、tx_*/before_* 列は非表示)** に変更。AnalyticsCatalogClient と同じ
「直結は read-only」規律の範囲内。

**根本原因の確定(同日追記・訂正)**: 当初「製品レベルの新発見(未修正バグ)」と報告したが、
追加検証で **旧サーバー × 新クライアントのバージョンスキュー**と確定:

- 除去漏れ(orphan index 名)は **core 3.18 で修正済み**
  (ライブラリモード実測: 3.16 → `secondaryIndexNames=[tx_state]` の矛盾メタデータを
  無検証で返す / 3.18 → `[]` に正しく除去)
- .129 Cluster ノードは旧版 core のため矛盾メタデータを gRPC で返し、
  **3.18 クライアントが再構築時の検証で拒否**(`ProtoUtils.toTableMetadata:1134`、
  例外はクライアント側の DB-CORE-10281)
- ライブラリモード 3.16 が「動いていた」のは検証が無かっただけで、メタデータは同様に壊れていた

**恒久解 = .129 Cluster ノードの 3.18+ への更新**(更新後は overview を ScalarDB scan に
戻せる)。ScalarRE の tx_state index(LazyRecovery 強制発動のための中途半端レコード検出)は
落とす必要なし。残る製品論点は「新クライアントが旧ノードのメタデータ出力を読めない」
互換性断絶のみ。

**解消確認(同日)**: ユーザーが .129 Cluster を 3.18 に更新 → プローブで
`secondaryIndexNames=[]`(正しい除去)と re_inbox / re_outbox の Cluster 経由 scan 成功を確認。
**JDBC 直読の回避コードを撤去**し(OverviewController を ScalarDB scan に復元、
mysql-connector-j 依存と app.monitor.* 設定を削除)、overview + 伝播スモーク
(viewRowsUpdated=8 往復)まで再検証済み。本件クローズ。
