## 発見・対処(環境)

- **teardown 時に minikube が停止していると k8s リソース削除がスキップされる**
  (teardown スクリプトの仕様)。今回その状態から setup したため:
  1. 前回環境の `analytics-server-cli` Pod が Error のまま残存 → setup の
     `kubectl wait` がタイムアウトするところを、Pod delete → 再 apply で回避
     (setup 側の wait が再作成 Pod を拾って続行、exit 0)
  2. PG の emptyDir が生き残り **erp.re_inbox に前回の配送イベント 1 件が残置**
     → 回帰テストは件数の増分(1→2)で判定した
  - 教訓: 完全な更地からの検証をしたい場合は minikube 起動状態で teardown するか、
    残存 Pod / 残置キューを意識する([[ops-lessons]] に追記)
