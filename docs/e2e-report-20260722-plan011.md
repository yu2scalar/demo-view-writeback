## 実装中に発見・修正したバグ

- `ViewService.sortRows`: sortOrder 未指定時に `keyColumns()`(= isKey 列)へフォールバックするが、
  集計 view は isKey 列が無く sorts が空 → `rows.sort(null)`(natural ordering)が Map に効かず
  ClassCastException。→ 集計 view は `groupColumns()` を既定ソートに、それも空なら sort をスキップ、に修正。

## 検証コマンド(要点)

```bash
# 集計 view preview / create（agg.json = GROUP BY material_id, SUM(material_volume), COUNT(project_id)）
curl -s -X POST localhost:8082/api/views/preview -H 'Content-Type: application/json' -d @agg.json
curl -s -X POST localhost:8082/api/views        -H 'Content-Type: application/json' -d @agg.json
curl -s localhost:8082/api/views/vw_material_summary          # 実体行
# read-only
curl -s -X PUT localhost:8082/api/views/vw_material_summary/rows   -d '{...}'   # 400
curl -s -X PUT localhost:8082/api/views/vw_material_summary/module -d '{...}'   # 400
# フィルタ（= / IN / LIKE、WHERE+GROUP BY 併用）は preview の filters で確認
```

## 結論

集計 view(read-only・Spark 全件計算・`_group_pk`)とカラムフィルタ(静的 WHERE・列/演算子/値・
= <> > >= < <= LIKE IN IS NULL IS NOT NULL・型別リテラル化)は API / GUI 両面で期待通り動作。
既存の非集計・更新可能 view の write-back はフィルタ併用でも一対一を維持。read-only 経路も enforcement 済み。
