### ユーザーフィードバック反映(2026-07-18 第2版)

1. View ビルダー — JOIN の可視化・編集性:
   - JOIN 線の起点側に **`種別: t1.col = t2.col` のラベル**を常時表示(白フチ付き、同一起点は段積み)
   - **接続済みカラムのハンドルを青色**でマーク
   - **JOIN 線をクリックすると編集ポップアップ**(種別変更・削除)。JOIN タブの一覧からも変更可
   - JOIN 種別を **INNER / LEFT / RIGHT / FULL に拡張**(SQL は LEFT OUTER JOIN 等の OUTER 表記で生成、
     線色も種別ごとに変更: INNER=青 / LEFT=紫 / RIGHT=緑 / FULL=橙)
2. 更新モジュールエディタ — フロー方向とコネクタ:
   - **縦フロー化**(入力ポート=ノード上辺中央、出力ポート=下辺。CSS 上書きで Drawflow を縦方向運用)
   - **エルボー(直角)コネクタ**(`editor.createCurvature` を上書きして直交パスを生成)
   - 分岐ノードの出力は下辺の左右2ポート(左=true / 右=false)

### ユーザーフィードバック反映(2026-07-18 第3版)

1. View ビルダー:
   - **ソートキー設定**を列マッピングに追加(ソート順 —/1〜5 の番号指定 + 昇順/降順。
     SQL に `ORDER BY <view列名> ASC|DESC` を番号順で生成、view_definition JSON にも sortOrder/sortDir を出力)
   - **JOIN 線もエルボー(直角)化**。縦線がテーブルカードに重なる場合は
     カード右側へ自動迂回するルーティング
2. 更新モジュールエディタ:
   - Drawflow は transform ベースでネイティブスクロールバーが出ないため、
     **右上にズームコントロール(− / 1:1 / ＋)+ 操作ヒント**(背景ドラッグで移動 /
     Ctrl+ホイールでズーム)を常設表示して操作を発見可能にした

### ユーザーフィードバック反映(2026-07-18 第4版)

1. View ビルダー — ソート順の重複防止: **他の列で使用中の番号はドロップダウンで選択不可(disabled)**。
   構造的に重複が起きない(代替案として検討した「重複時に自動スワップ」は不採用)
2. 更新モジュール — **Begin ノードは追加しない**(設計判断、ユーザー質問への回答):
   トランザクション境界は実行エンジンが管理する。更新モジュール全体が1つの ScalarDB Tx 内で
   実行され、「開始」ノード= Tx begin + 入力受信。明示するため開始ノードの表記を
   「開始 (Begin)」に変更(表記はユーザー指定 2026-07-18)。Commit/Abort は Tx API 呼び出しではなく**フローの終端結果**
   (正常確定 or 検証NGによる中断)を表すノードであり、ユーザーが Begin の置き忘れ・
   二重 Begin・Tx 外操作を作れてしまう構造を避ける
- 分離の経緯: 当初 plan-001 の FC-5 だったが、モックデータのみで独立に検証でき、

## 1. 検証対象の2エディタ

目標アーキテクチャ(plan-001 §3)のうち GUI が第一の課題とされている。対象は次の2つ:

### ① View 定義 Editor(SSMS 風)
- SQL Server Management Studio のビューデザイナに類似した構成
- 左ペインのテーブル一覧から**ドラッグ&ドロップ**でキャンバスに配置
- **JOIN の定義も GUI で**(テーブル間の結線)
- 利用テーブルの各キーは**自動登録・除外/変更不可**。その他カラムは選択式
- カラムごとに表示/非表示・**更新可否**のチェック
- **生成 SQL と Preview の表示**(SSMS 類似のペイン構成)

### ② 更新モジュール Editor(RPA 風フローチャート)
- 更新対象レコードに対する「簡易な確認を含めたコントラクトのようなもの」を GUI で構成
- 最低限のコントロール:
  - 既存レコードの読み込み & 変数格納
  - 値の比較検証(一旦 INT のみ)
  - 分岐
  - 更新
  - フローチャート上で管理する変数機能
- デフォルトで、選択された更新対象カラムがあるテーブルの Model 変数と更新コントロールを表示
- (旧 demo-cache-writeback での在庫・マスタ有無チェック相当が組めること)

## 2.5 既製ツール調査結果と技術選定(2026-07-18)

ユーザー提案の「DbGate + freeflowcharts.app の組み合わせ」を調査した結果、**両者とも組込部品としては不採用**
(UX リファレンスとしては参考にする):

| 候補 | 評価 | 理由 |
|---|---|---|
| DbGate Query Designer | 不採用(UX参考) | SSMS 風 D&D+JOIN 線はまさに欲しい UX だが **Premium(有料)限定**。スタンドアロン DB マネージャのため、Analytics カタログからのテーブル供給・キー列の除外不可制御・更新可否フラグ・view_definition への JSON 保存をいずれも差し込めない |
| freeflowcharts.app | 不採用 | エクスポートが PNG/SVG/Mermaid のみで**構造化 JSON 出力なし**。ホスト型でセルフホスト/埋め込み/OSS の記載なし。ノードに実行セマンティクス(テーブル/カラムバインド)を持たせられない |

**決定(ユーザー承認 2026-07-18)**: 更新モジュールエディタ = **Drawflow**(MIT、vanilla JS、
ノード定義+JSON 入出力が標準)、View ビルダー = **自前 HTML+SVG** で SSMS 風レイアウトを実装。
両者とも vanilla JS で前身デモの GUI と流儀を揃える。

## 3. 留意点

- プロトタイプはスロー可能(本実装に流用しない前提で速度優先)。ただし出力 JSON の形は
  本設計に引き継ぐため丁寧に検討する
- 認証・保存 API は不要(モックデータ、ローカル静的ファイルのみ)
